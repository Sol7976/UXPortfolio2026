## Writing style
- NEVER use em-dashes (—) anywhere, in any copy or output. Use commas, colons, or restructure the sentence instead. This is a hard rule.

## Type (Hanken Grotesk, one family)
- Display / headlines: Light 300, tracking −.02 to −.035em (hero 48–66px, section 34–42px). Every display heading and band statement carries `text-wrap:balance`, so a two- or three-line headline breaks into even lines instead of a long line plus a stub. Running text keeps `text-wrap:pretty`.
- Titles / card names / metrics-in-rows: Medium 500, tracking −.01em (20–26px).
- Body: Regular 400, 18px / line-height 1.6–1.7, colour #4c4b45. The homepage hero lede is 21px, one step above body.
- Kickers / labels: Semibold 600 tracked caps, 9–11px, tracking .13–.22em, colour #67665f (AA-safe).
- Metrics: Light 300, 30–46px, tracking −.02em, with a caps-10px #67665f label under. The metric number is inked #1a1a17 (or cream on black), never yellow: yellow as text on light fails AA.
- Editorial accent only: Newsreader italic (articles / writing voice). Never in UI. JetBrains Mono only for hex / code hints / image-placeholder captions.
- Numerals never take a trailing dot: index and step numbers read `01`, `02` (never `01.`), and metric figures stand alone. No dots in numbers, anywhere.

- Hover gotcha: `style-hover` compiles to a `:hover` class rule, which loses to inline `style` on specificity. ## Motion & animation (engine: `cs-interactions.js`)
- Scroll wipe on clipped/transformed imagery (`data-tilewipe` + `data-tw-i`, both Laced auth pages): the engine's `img[data-reveal]` clips the image's own box, so on a scaled or translated crop the wipe front lands unpredictably. Instead put `data-tilewipe` on the FRAME (the `overflow:hidden` wrapper) and clip that: resting `inset(0 0 0 0)`, seeded to `inset(0 0 100% 0)`, played on scroll position (not IntersectionObserver: half-clipped tiles never cross a threshold). Duration is the house 1700ms for every element regardless of height, staggered `data-tw-i × 150ms`. Implemented as `_wipes()` in each page's logic class, called from `_tick()`.
- House curve `cubic-bezier(.4,0,.2,1)`. Evidence "draws in" once when scrolled into view (IntersectionObserver at 0.2 + a scroll rescan), never loops. Only the client marquee (46s linear) and the hero / dev-build videos loop. Hover/state transitions are .18s ease.
- Hooks: `data-reveal="down|right"` clip-path wipe 1700ms (charts, IA map, screenshots); `data-arc` + `data-c`/`data-off`/`data-delay` donut ring 1700ms; `data-bar` + `data-w`/`data-delay` bar grow 1150ms; `data-tabgroup` + `data-view` (with `data-on`/`data-off` style strings) driving `data-panelgroup` panels = segmented toggle; `data-wf="reveal"` scroll-linked wireframe→design morph via a `--p`/`--pos` custom property.
- Hook gotchas (verified on E.ON): `data-arc`/`data-bar` are only seeded + observed inside a `[data-panelgroup]` ancestor, so wrap a standalone donut/bar set in a `[data-panelgroup="…"]` even with no tabs. `data-reveal` fires only on `<img data-reveal>` (observer selects `img[data-reveal]`); placeholder tonal-block divs never animate, so reserve reveals for real imagery and use `data-arc`/`data-bar` for numeric evidence on placeholder pages. Donut geometry: `stroke-dasharray` = circumference (2πr); `data-c` = circumference; `data-off` = circumference × (1 − fraction shown); rotate the arc `-90°` around its centre to start at 12 o'clock (r=52 → circ 326.73, 86% → data-off 45.7). Two tab systems exist: the engine's `data-tabgroup`/`data-view`/`data-panelgroup` (preferred, replays arcs + reveals on switch) and a bespoke inline `data-tabs`/`data-tab`/`data-panel` click script (in `HSBC Premier Case Study.dc.html`); don't mix them.
- Reveals use a CSS clip-path transition whose resting state is fully visible, NOT WAAPI: WAAPI clip-path silently no-ops in this runtime and would clip the data layer away permanently. Numeric props (stroke-dashoffset, width) animate fine via WAAPI.
- Carousel connector line (E.ON IA carousels, desktop + mobile): the hairline lives INSIDE the scrolling track (`position:absolute` first child of the `position:relative` track), spanning first-card stem centre to last-card stem centre via offsetLeft maths in `setRailStatic`; it scrolls with the cards, so it never animates or resizes on navigation. Never position it as a sibling overlay recalculated per page (it visibly slides), and never drive it from raw `scroll` events. Track heights fit per instance (`_fitTrack`), positions relative to the first card, refit on resize / font load / ResizeObserver.
- Multiple case studies on one board (`Final designs.dc.html`) share the DOM, so every interactive hook id/key must be namespaced per page (mobile uses `-m` suffix: `ia-m`, `ca-m`, `eon-ut-m`, `eon-ia-rail-m`); duplicate ids make one page measure another's elements.
- `cs-interactions.js` seeds, observes and re-scans on every DC re-render via `window.__csRescan()` (call it from `componentDidMount`/`componentDidUpdate`). Copy the file into any page that uses these hooks.

## Imagery scaling (case-study evidence)
- Animated charts split the source PNG into a static AXIS layer (names/gridlines/numbers on a transparent background) + a DATA layer (the values), stacked in one `display:grid;place-items:center` cell with the same `object-fit:contain`; only the data layer carries `data-reveal`. Flood-fill the source's white to the panel surface so boxes/lines read on grey, and keep the axis background transparent so the panel shows through (no white ghost box on load).

- Video: frame it (hairline + radius 14 + soft shadow) and crop scrollbars/black bars with an `overflow:hidden` wrapper over a slightly oversized video (`width/height:calc(100% + Npx)`), `object-position:top left`. Autoplay muted loop playsinline; boot via the `data-hero` play loop.

## Wide-screen build conventions (locked 13 Aug 2026, ArcelorMittal is the reference)
`work/arcelormittal/index.html` + the `.cs-*` layer of `styles.css` are the reference implementation for every remaining case study. Build from these, not from first principles.

**Build status.** All five routes exist: `work/arcelormittal/`, `work/hsbc-premier/`, `work/eon-app-ia/`, `work/laced-authentication/` (built 14 Aug 2026, sections 17–18 of `styles.css`) and `work/laced-customer-support/` (built 14 Aug 2026, sections 19–20 of `styles.css`, page script + `cs-interactions.js` + `lcs-pie.js`). The last two are not yet signed off by Thomas. The homepage is at the root.

**Precedence.** The design files in `_design` are the source for layout, copy, colour and every authored number, but parts of them are stale. Where a design file disagrees with the rules below, or with a written note from Thomas, these rules and the note win. Recent case: the re-issued desktop files still carry the step-marker label at 11px and `max-width:552px` on band statements; the build uses 12px and 5/12 of the column. Check `_design` mtimes before assuming a file is current.

**Type: only measures rescale with the column, never sizes.**
- Cover title `h1` 24ch · step title `h2` 48ch · step body 63ch · step body on black 55ch · outcome statement 40ch · pull-out line 70ch. The two body measures were 75ch/66ch until 13 August; counted on the built pages that ran 89 characters a line at the 1680 cap, past the 45–75 comfortable range and over the WCAG AAA limit of 80. Characters per line is font-size independent, so this is unrelated to body going to 18px.
- Band statement (the Light-300 32px context and business-problem statements, one shared measure): `max-width:calc(var(--col) * 5 / 12)`, so 460px at the authored 1104 column and 660px at the 1584 cap.
- Business problem body: shares BOTH vertical edges with the step 01 body at every width. Its grid column is the step 01 copy cell, `1fr calc((var(--col) + 96px) / 2.1 - 96px)`, which sets the left edge; the 75ch cap sits on the paragraph, which sets the width. Never cap the grid column instead: that shortens the last track and slides the paragraph right (32px off at the 1680 cap). Where a study's step 01 is a full-width two-up rather than a padded copy cell (HSBC), the column is that grid's own body cell, `1fr calc((var(--col) - 64px) / 2)`; the principle is unchanged.
- `--col` is the band content column (1104 authored, 1584 capped), set by the page script.
- Text inside a scaled figure holds its authored size: figcaptions live outside `.cs-fig`, chart-internal labels take `.cs-noscale`. The one exception is a `data-arc` ring number, which rides the zoom so it keeps its proportion against the ring.

**Figures scale uniformly with the column.** `data-fit` on the figure cell carries the width it had at the authored viewport; the page script divides the cell's current width by it into `--k`; CSS zooms the cell. Everything inside then keeps its authored geometry and simply paints larger, so tile sizes, gaps, stagger offsets, `object-position`, crop windows, `r`, circumference, `data-c`, `data-off`, `stroke-width` and `data-w` are never re-derived. Rules that go with it:
- `[data-fit]{min-width:0}`, or a zoomed cell feeds its width back into `fr` track sizing and `--k` creeps above 1 at the authored width.
- `.cs-fig` wraps the evidence ALONE. Segmented toggles, carousel arrows and fraction counters sit outside it and stay at authored size; a safety rule counter-scales any that end up inside. Tap targets stay 44px because of it.
- Where a cell holds both a control and its evidence, the cell is not zoomed: it scales its own padding by `--k` and `.cs-fig` inside carries the zoom.
- Bleeding modules clip at the content column's edge, the same edge every other band's content stops on, not at the viewport. That IS the authored crop: at `--k` the drawn overruns scale with the artwork.
- Never rescale a module to close a gap to the screen edge. A tile grid or a column of screens keeps its structural edge with its first unit whole; only continuous artwork may shift.

**Components.** Meta rows are `display:flex;justify-content:space-between;align-items:baseline;gap:24px` (20px mobile) with the value `text-align:right`. Step markers are 12px, number and label, both breakpoints. The brand mark is `#201C16`, never the browser's black. Newsreader italic loads on every case study.

**Structure.** One file per route serving both designs. Author the markup in mobile reading order, copy before evidence, and move the evidence with `order:-1` on desktop. Fence any modifier on a class the homepage also uses inside `@media (min-width: 900px)`, or it outranks the homepage's mobile block. Verify at a 1200px viewport, where the content column is 1104px and the build and the desktop design line up 1:1.
